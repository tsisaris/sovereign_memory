Fix dialect overrides and execution context mapping safely without global patches.

The nested execution context and `pass`-only overrides were completely deleted. `duckdb_engine` inherits `PGExecutionContext_psycopg2` which relies on `cursor.connection.notices`. The adapters properly provide `connection` and `notices` directly, solving this robustly without disabling functionality or using unapproved `# type: ignore` exceptions.

`duckdb.TransactionException` in the `duckdb_sqlalchemy_async_bridge` module's `rollback` handler now explicitly checks the message "TransactionContext Error: cannot rollback - no transaction is active". It only catches this specific condition (to handle legitimately aborted out of order transactions) and no longer blindly swallows the entire class.

The fallback connection wrapper `AsyncAdaptFallback_duckdb_connection` inherits from `AsyncAdaptFallback_dbapi_connection` cleanly combining logic without explicitly bypassing `__init__`, assigning `await_`, or writing redundant code. Unnecessary redundant overrides like `do_rollback`, `do_commit`, `get_driver_connection`, and `_ = cls` vulture tricks were deleted.
