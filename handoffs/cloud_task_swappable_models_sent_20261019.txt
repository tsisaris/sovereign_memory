THE OWNER'S RULINGS (all settled, do not re-argue):
1. Memory keeps a labelled copy of every number it receives inside its one DuckDB file. Memory never makes numbers of its own: it never runs a model, never measures text and never cuts text, and it never calls agent_embedding.
2. The door that returns numbers for a single search question belongs to agent_corpus. Build memory's side so it calls that door through a declared supplier interface. The end-to-end search proof waits for that door.
3. Ground-truth judgments point to events and never copy event text. Forgetting hides an item; ground truth keeps its pointer and the record of the judgment, and a case whose event was forgotten is marked source-removed and leaves training and held-back scoring.
4. Four tunable settings: the score used to compare combiners, the held-back share, the smallest held-back set that may decide, and the merging constant. They live in memory's declared parameter records, are read at run time, are reported as the value achieved, and are never written into code (project Law 32). The merging constant starts at 60: Cormack, Clarke and Buettcher, SIGIR 2009, say "k = 60 was fixed during a pilot investigation and not altered during subsequent validation". Choose no value for the other three; seed them from the owner's declared source if one exists, and if the repository has no declared source for settings, say exactly that in the pull request and use the narrowest mechanism the repository already uses for configuration, validated at start so a missing value fails clearly.
5. Memory owns its relevance judgments and its own review screen. agent_corpus owns judgments about documents. Neither copies the other.
6. Memory's originals reach agent_corpus as a collection declared by a source row in agent_corpus's registry (a registry row, not code). That is an agent_corpus requirement, not memory code.

WHAT TO BUILD (follow the amendment text; this list is its order of work):
A. Model registry: a model is a row (model id, revision, width, kind embedding or classifier, supplier collection and recipe, date registered). Memory names no model in code. Adding a model is adding a row and receiving its numbers.
B. Per-model numbers tables named from the registry (DuckDB fixed width means one table per model revision), each row carrying event id, piece id, model id, revision, width, the supplier's text fingerprint and the receive time. Classifier scores the same way, width equal to class count. Replace the one-identity-per-tier rule, EmbeddingIndexMismatch and the single identity in the rebuilds table. A model whose numbers are missing or whose label no longer matches the supplier's current row is stale for that model only: mark its rows stale, ask the supplier to recompute, replace only that model's rows on arrival, touch no other model and no original. Search meanwhile uses fresh models and says which were left out and why; never treat a stale model as an empty result.
C. Pieces: the unit memory stores is the piece the supplier cut (text, id, position in its source event, and its event id). Change the Cognee chunk tier from one event, one chunk to one piece, one chunk, and switch Cognee's own cutter off on the memory path. Every hit rolls up to its event, and the existing checks (live, not removed, not expired, visible to the asker) still decide whether it may be shown.
D. Retire the direct-call adapter: remove packages/mem0_duckdb/src/mem0/embeddings/agent_embedding.py and the agent_embedding branch of the relational tier's identity code from the working tree and from every configuration (history stays in git). Give Mem0 and Cognee an embedder object that looks up received numbers for a text and, where none exist, reports "numbers not yet supplied" as named pending work. It never invents a vector.
E. Search: one ranking per fresh model per memory kind from its own numbers; a combiner registry (id, rule, models used, settings, proposer, held-back result, exactly one current); reciprocal rank fusion as the starting current combiner (score is the sum over models of 1 divided by merging constant plus rank); every answer reports the combiner that produced it. A candidate combiner replaces the current one only if it scores better on held-back ground truth; with too few held-back cases the current one stays. A trained combiner comes from agent_uagent_builder as an artifact: memory never runs it; it hands the builder the held-back inputs without judgments and scores the returned merged rankings itself.
F. Ground truth, append-only: cases (id, kind, memory kind, input, events, time, training or held-back, the split fixed once from the case id), model outputs for every model that took part (id, revision, width, ranking or scores, current combiner id), and judgments (who, when, verdict, chosen or typed answer, note; a later judgment is a new row that supersedes, nothing overwritten). An export manifest (case ids plus a content fingerprint) so a training run can be repeated exactly. Cases carry their memory kind so per-kind and one-shared decision models can be compared on the same held-back cases. Training itself belongs to agent_uagent_builder; build none.
G. Review screen: lists cases where models disagreed (and cases the owner chooses to judge), shows the original beside each model's answer, the owner picks one or types the right one; it follows the same visibility rules as every other read and never shows a forgotten item.
